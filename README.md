# ӨRLEU BASE

Система учёта компьютерной техники и имущества филиала АО «НЦПК «Өрлеу» ИПР по Акмолинской области.

**Сайт:** https://slickmine.github.io/orleu-base/

- В программе видно, где находится каждая единица, за кем она закреплена и в каком состоянии.
- Основные средства (ОС) и ТМЗ учитываются отдельно.
- Технику можно перемещать между кабинетами и сотрудниками, все перемещения сохраняются в истории.
- У каждой единицы есть постоянный QR-код. При сканировании открывается её карточка.
- Инвентаризацию можно проводить с телефона: найденное отмечается зелёным, не найденное красным.
- Отчёты выгружаются в Excel.
- Есть две роли: **администратор** может всё, **просмотр** может только смотреть.
- Работает на компьютере и телефоне. На телефон программу можно установить как приложение: «Добавить на главный экран».

## Как устроено

- **Сайт** (папка `docs/`) лежит на GitHub Pages. В нём только интерфейс.
- **Данные** хранятся в базе [Supabase](https://supabase.com) (PostgreSQL).
  - Вход по почте и паролю.
  - Права проверяет сама база: правила RLS и функции из `supabase/schema.sql`. Человек с ролью «просмотр» не сможет ничего изменить, даже в обход интерфейса.
  - Ключ `anon` в `docs/config.js` публичный, хранить его в открытом репозитории можно. Без входа по паролю этот ключ не даёт доступа к данным.
  - Ключ `service_role` и пароль базы в репозиторий **не кладите никогда**.

## Первоначальная настройка (один раз)

1. **Supabase.** Создайте проект на supabase.com. Затем: SQL Editor → New query → вставьте весь файл `supabase/schema.sql` → **Run**.
2. **Данные из Excel.** На компьютере выполните:
   ```
   pip install -r requirements.txt
   python tools/make_seed.py "..\Исходные данные"
   ```
   Появится файл `supabase/seed.sql`. Вставьте его в SQL Editor и нажмите Run.
   - Файл содержит ФИО и стоимости, поэтому в GitHub он не попадает.
   - Отчёт о том, что не сопоставилось, сохраняется в `supabase/import_report.xlsx`.
3. **Вход.**
   - Authentication → Sign In / Providers: **выключите «Allow new users to sign up»**, чтобы посторонние не могли зарегистрироваться.
   - Authentication → Users → **Add user**: укажите почту и пароль, отметьте «Auto Confirm User». **Первый созданный пользователь автоматически становится администратором.**
4. **Подключение.** Впишите в `docs/config.js` значения `SUPABASE_URL` и `SUPABASE_ANON_KEY` (Project Settings → API).
5. **GitHub Pages.** Settings → Pages → Source: *Deploy from a branch*, Branch: `main`, папка `/docs` → Save. Через минуту сайт откроется по адресу выше.

## Пользователи

- **Добавить пользователя:** Supabase → Authentication → Users → Add user. Новый пользователь получает роль «просмотр».
- **Сделать администратором:** в программе «Настройки → Пользователи» нажмите ✎.
- **Сменить свой пароль:** «Настройки → Сменить пароль».
- **Если пароль забыли:** Supabase → Authentication → Users → … → Reset password.

## QR-коды

QR-код ведёт на `<адрес сайта>/#/a/<инв. номер>`. Адрес берётся автоматически — тот, по которому открыт сайт (его можно задать вручную в `docs/config.js`, `SITE_URL`).

**Не переименовывайте репозиторий и не меняйте адрес после печати наклеек**, иначе старые QR-коды перестанут открывать карточки.

## Инвентаризация

1. Откройте «Инвентаризация» → «Начать». Выберите кабинет или весь филиал.
2. Нажмите «Включить камеру» и наводите её на наклейки. При каждой отметке будет сигнал и зелёная строка.
3. Цвета в списке:
   - красный: техника не найдена;
   - жёлтый: техника числится в другом кабинете. Её можно сразу «Переместить сюда».
4. Нажмите «Завершить» и выгрузите отчёт в Excel.

## Сохранность данных

- База хранится в Supabase. Она не зависит от браузера и компьютера: можно заходить с любого устройства.
- Бесплатный проект Supabase засыпает после 7 дней без запросов. Чтобы этого не было, сценарий `.github/workflows/keepalive.yml` раз в 3 дня обращается к базе.
- Резервная копия: «Настройки → Скачать копию базы». Скачивается Excel со всеми таблицами. Делайте её раз в неделю и храните на флешке или в облаке.

## Для разработчика

- `docs/`: интерфейс на чистом JS.
  - `data.js`: работа с Supabase.
  - `app.js`: экраны.
- `supabase/schema.sql`: таблицы, роли, правила доступа, функции перемещения, инвентаризации и ТМЗ.
- `tools/`: загрузка из Excel и генерация `seed.sql`.
- Проверка схемы на локальном Postgres:
  ```
  pip install -r requirements-dev.txt
  python -m pytest tests
  ```
- Локальный запуск сайта:
  ```
  python -m http.server 8090 --directory docs
  ```
